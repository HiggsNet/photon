# Photon v0.7.0

本版集中重构 Gossip、Linux daemon 和 Windows 客户端，减少重复状态与后台任务，明确状态更新和资源清理的归属。提供 Linux amd64/arm64 归档与容器镜像，以及 Windows amd64 便携包。

## 主要变化

- Gossip 使用 PING 摘要直接启动同步，统一快照处理、查询和诊断，移除旧通知及重复调度。修复同步超时、UDP 补传、提交后转发，以及调度器计算等待时间与启动计时器之间的到期竞争。
- Linux daemon 保留事件循环内的同步系统协调，明确 firewall、routing、IPsec 的依赖并缩小重建范围。公网地址采集独立执行，后台任务退出时取消并等待；修复请求取消、超时、入网发布时序与 BIRD/StrongSwan 收尾。
- 上游路由通过 netlink 管理带归属标记的对象，适配 Ubuntu；健康探测隔离不同目标及旧任务的结果。节点撤销后重启时，根据身份、确定性连接标识和 XFRM 归属恢复仅用于拆除的实例，清理残留 SA 与接口。
- Windows 原生界面更新状态总览和导航，提供独立 Mihomo 代理管理，支持同一网关并行 IPv4/IPv6 隧道。修复 IKE 规划刷新、控制流退出和设备回收，将耗时回收移出状态锁；FlClash 集成更新 Photon 规则编辑、状态表格与稳定配置。
- 更新 flake 的 nixpkgs 锁定，Nix 产物的版本命令显示声明的版本号，并保留独立的提交与修改状态。验证实际构建及两种架构的构建计划；Go 依赖未变，flake 与旧式 Nix 入口沿用一致的依赖校验值。

## 升级前检查

1. 备份配置、身份和一致的数据库副本。本版只读取 Common schema 2；旧 aggregate 或 Common schema 1 先用 v0.6.6 完成迁移。回退时恢复升级前备份，不把新版数据库的可回读样例当作通用降级保证。
2. 删除旧配置中的 `gossip.max_sync_zones`。尚未实现的 `health.metrics.remote_write_url`、`health.metrics.remote_write_queue_capacity` 和 `observer.ui_path` 现在会明确报错，也需删除。
3. 独立同步命令 `advanced sync serve` / `advanced sync once` 已删除，长期同步使用 `photon daemon`。外部脚本及 API 客户端需核对 [操作与兼容性说明](https://github.com/HiggsNet/photon/blob/v0.7.0/docs/operator-compatibility.md) 中的诊断和查询字段变化。
4. 新旧节点的普通同步和 TCP 大对象拉取已验证。若 TCP 不可用，v0.6.6 节点无法按新版请求完成 UDP 分块回退；依赖此路径的节点需一起升级。本版保留该已知协议边界。

## 验证范围

已完成 Go 1.25.0 完整检查、全量并发检查及常规 smoke。隔离 Linux 环境验证了真实 StrongSwan/XFRM 建链与重启恢复、撤销清理、轮换和换钥、BIRD/Babel、防火墙、故障丢包，以及 SOCKS5 服务连通。Windows 已完成原生后台回归、服务端到端和交互桌面 GUI 验收。

发布流水线另检查正式标签、Windows 原生运行、Linux 双架构归档和容器镜像；归档附 SHA256 校验文件。长期实网观察、物理换网和生产灰度仍属于后续部署验收，本次发布不包含节点部署。
