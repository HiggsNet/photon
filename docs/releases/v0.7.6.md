# Photon v0.7.6

修复节点撤销后使用新密钥重新授权时，旧身份记录阻挡新记录同步、
网关继续使用旧隧道公钥而导致认证失败的问题。

## 主要变化

- 合并记录时先验证新记录，再按当前授权重新验证已有记录。已经失效的
  旧记录不再以相同或更高版本号阻挡有效的新记录。
- 新旧记录都有效时，继续沿用原有版本与前序哈希检查。无效新记录仍被
  拒绝，不会修改当前状态。
- 同版本不同内容、直接下一版本的前序哈希不匹配，会输出
  `record_conflict` warning，包含来源 peer、Zone、记录名、双方版本和
  记录哈希。普通旧版本及相同记录不会作为冲突报警，日志不包含记录内容。
- 延续 v0.7.5 之后主分支已有的 Windows 构建缓存和耗时诊断改进。

## 兼容性与升级

不新增记录字段，不改变签名格式、Gossip wire version 或数据库 schema，
也不要求重新生成密钥或重新申请授权。v0.7.0–v0.7.5 可直接升级；
更早版本仍遵循 [v0.7.0 升级要求](v0.7.0.md)。

受影响的服务器节点需要升级，才能用新逻辑接收客户端的新记录。
仅升级 Windows 客户端不能修复旧版服务器上的合并逻辑。已经采用新授权、
但仍残留旧记录的服务器也适用；新记录再次同步时会重新判断旧记录有效性。

升级前备份配置、身份数据库及代理模板。修复不需要删除数据库或手动替换
公钥。真实恢复应以服务器收到正确的新公钥、隧道认证成功及业务连通为准。

## 验证

回归覆盖新授权到达、已采用新授权但残留旧记录、旧版本为 1 或 100、
无效新签名拒绝、真实版本与前序哈希冲突，以及无变化同步时的 warning。
相关检查已在 Windows 虚拟机原生运行通过。

正式发布提供 Linux amd64/arm64、Windows 原生客户端、Photon-FlClash
便携包与 EXE 安装版及 SHA256 校验文件。发布不包含生产节点部署。
