# Photon v0.7.7

photon-services v2 增加 TrustTunnel，并统一使用 Mihomo 承载 HTTP、SOCKS5
和 TrustTunnel。Photon-FlClash 增加出口选择，按用户勾选生成代理配置。

## Photon-FlClash 出口选择

- 在 **Photon → 代理服务** 分别勾选 SOCKS5、HTTP、TrustTunnel，首次默认
  只启用 SOCKS5。HTTP 不承载 UDP；需要认证且尚未提供凭据的 HTTP 入口
  不加入候选。
- 按实际发布地区勾选，支持排除整个地区；固定节点勾选只控制该节点的
  `local` 出口。地区及 Global 任播按协议、目的地址和端口合并，不随
  某个发布者的固定节点勾选而消失。
- 点击 **保存出口选择** 后更新已有 Photon 配置并关闭旧代理连接。
  选择保存在本应用中，重启和切换 Photon 配置后继续使用；新发现的
  地区、节点默认纳入已启用协议，已排除项目在撤回、重现后仍保持排除。
- 筛选同时作用于内置代理组和模板引用的 `photon-services`，保留模板
  自带的其他代理。没有选中出口时拒绝 Photon 代理流量。

## photon-services v2

- HTTP、SOCKS5、TrustTunnel 独立配置、渲染及发布，统一使用 Mihomo。
  保留 v1 HTTP/SOCKS5 配置兼容，支持 `--only` 选择协议。
- 新增独立 HTTP 和 TrustTunnel 签名服务记录及客户端解析；TrustTunnel
  使用 HTTP/3，支持 TCP/UDP，并由发布的证书指纹验证服务端身份。
- TrustTunnel 当前只支持普通、非 shared assignment 的 `local` 出口。
  提供 NixOS 独立部署、启动前 ACL、共享路由清理和幂等撤销支持。

## 升级与兼容性

使用 HTTP/TrustTunnel 新记录，需要发布节点的 CLI、daemon 和消费端
均支持相应协议；新 CLI 连接旧 daemon 会明确失败。新增的服务能力不要求
删除数据库或重新生成节点身份。服务配置、部署与限制见
[服务说明](../new/services.md)，FlClash 操作见
[客户端说明](../../app/photon-flclash/README.md)。

升级前备份配置、身份数据库及代理模板。旧版本迁移仍遵循
[兼容性说明](../operator-compatibility.md) 和 [v0.7.0 升级要求](v0.7.0.md)。

## 验证与发布范围

本地验证覆盖出口筛选、选择保存、空选择拒绝、任播合并、模板引用和
TrustTunnel 配置，以及 Go 测试、静态检查、Linux 构建、Windows 交叉构建
和常规 smoke。正式发布流水线另执行双架构 Linux 构建、Windows 原生测试、
FlClash 检查、Windows 打包及安装程序生命周期检查。

附件提供 Linux amd64/arm64 归档、Windows 原生客户端、Photon-FlClash
便携包和 EXE 安装版及 SHA256 校验文件，容器发布至 GHCR。
发布不包含现有节点部署；真实 Windows 桌面及业务流量仍需安装后验收。
