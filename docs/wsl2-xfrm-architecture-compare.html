推荐

ApplyTransportLink                  # 不再 type-assert 路由接口
  xfrm.EnsureNamespace
  ipsec.LoadConnection
    driver 构造时已决定是否剥 if_id
  xfrm.EnsureInterface              # 附着点不变量含路由
    InterfaceXFRM: add phx* + multicast
    PolicyXFRM:    noop device + lo route
  xfrm.AssignAddress
    InterfaceXFRM: prune + replace on phx*
    PolicyXFRM:    accumulate on lo

ReconcileActionAdopt / Repair / Staged
  同样走 EnsureInterface
  # Adopt 不再是“什么都不做”

Daemon.xfrmLinkStateMatchReason
  委托 xfrm.InspectLink 的匹配结果
  # daemon 不再读 xfrm_backend

点一行，两侧详情会同步。这不是新抽象清单，是「知识该停在哪一层」。

层 现在知道的 推荐知道的
YAML / 构造 xfrm_backend 渗入 group、两个 driver、daemon 只在 factory 出现一次，选出 adapter
TransportLinkSpec InterfaceName = "lo" 冒充设备 仍是 phx<id> 资源名；附着点由 adapter 解释
XFRMDriver 一个类型 + Backend flag，处处 if policy 两个 adapter，运行期零分支
对端路由 optional 接口；Create 双调；Adopt 漏；错误被丢掉 EnsureInterface 的不变量；所有 apply 路径自然带上
Daemon 匹配 policyXFRMBackend() 放宽 multicast 只消费 InspectLink；不读 backend
Owner / teardown 名字必须 phx* → lo 实例拆不掉 实例名从未变成 lo，校验不用改语义
Firewall WSL2 提交里给所有 overlay INPUT 加 invalid accept 按「解封装后 ct invalid」的流量语义留下，与 backend 解绑
BIRD / rotate 认 phx*；rotateSpec 无条件打回设备名 调用方继续看资源名；adapter 自己处理无设备

推进顺序（先补裂缝，再搬知识）

  1. Owner 名不要变成 lo — 现在就能修的正确性洞，卡住 teardown/cleanup。
  2. 路由和 lo 地址累积收进 Ensure/Inspect — 删掉 XFRMPeerRouteInstaller 和 daemon multicast 特例。
  3. firewall invalid-accept 按流量语义留下 — 文档从 WSL2 挪到防火墙，不做成 backend 开关。
  4. 再拆 SystemXFRMDriver 为两个 adapter — 那时 xfrm_backend 只在构造函数出现一次。
